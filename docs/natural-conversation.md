# 自然对话改造

这次借鉴 MaiBot 对发言时机、人格与表达分离、表达来源校验的处理方式，接入 tg-aibot 现有的 Telegram、SQLite 和模型接口流程。实现为本项目重新编写，不依赖 MaiBot 的 Python 运行环境，也不新增嵌入模型或后台模型调用。

## 实际变化

- 连续文字先收齐：同一群、同一 Topic、同一发言者相邻的连续文字默认等待 900ms，最长 3 秒，再合成一个请求。原问题和补充都保留在上下文中。媒体和单独引用的问题分别处理。
- 继续聊不必每句 @：机器人回应过的人，在 120 秒内继续发言，可以进入接话判断，不受随机插话的 60 秒冷却、消息数和抽签限制。模型仍可判断是否有必要回应。致谢、结束语、回复其他人、提及其他人，以及其他群友已经接管对话时，不走这条捷径。不同 Topic 独立。
- 正在生成也能接收补充：同群请求依次处理，不同群可并行；同一人补充上下文时，合适的旧答案会被取消发送。显式问题的回答义务会传给补充后的新请求。等待任务最多 8 个，优先保留直接提问；队列全是直接提问且已满时，会提示稍后再试。
- 识别聊天对象：保存 Telegram 发言者编号与机器人回应的原消息编号。同名群友、匿名管理员和频道发言分别处理。旧聊天记录没有编号时，不猜测其身份。
- 语气随对话调整：参考最近真人文字的句子长度和表情使用，结合对方是在吐槽、接梗还是认真求助。把自己最近的说法交给模型作去重参考，减少固定开场、模板安慰和反复总结。保留正文中的换行。
- 旁观和收住：群里已经继续聊天时，取消过时的随机插话和冷场回复；被直接提问仍针对原提问者回答。安静时段保持对自然接话的限制，直接 @ 和明确昵称称呼仍可触发。
- 私聊普通消息可直接进入回复流程，无需 @ 自己。

这不会改变所选模型本身的语言能力。风格规则能改善输入和互动机制，真正的自然程度还需要部署后用所选模型观察。

## 表达学习

正常的回复请求允许模型附带一条可选的表达建议，不额外发起学习请求。程序写入前核对来源消息编号、真人标记和原文字面内容；模型编造的原话、机器人自己的话、转发和媒体内容不能写入。常见身份、凭证、链接和指令特征还会被过滤。

表达只作为语气示例，不能当作人物事实或系统规则。已确认的群友偏好、黑话含义和群内约定，继续由管理员通过 `/memory_add` 管理，程序不自动给群友编造人物档案。

每个群的每个 Topic 最多保存 60 条表达，默认 30 天过期，维护任务会物理清理。调用时按当前文字与使用场景的双字片段匹配，最多选 3 条供模型参考；没有匹配就不注入。这里没有语义向量检索，模型也可能完全不提出值得学习的表达。

管理员命令：

| 命令 | 用途 |
| --- | --- |
| `/expressions` | 查看当前 Topic 学到的表达，展示最常用的前 30 条及 ID |
| `/expression_del ID` | 删除当前 Topic 的一条表达 |
| `/expression_clear` | 清空当前 Topic 学到的全部表达 |
| `/memory` | 查看管理员确认的记忆 |

`/context_clear` 清除短期聊天上下文；表达集合需单独使用 `/expression_clear` 清除。删掉的表达如果之后又被群友使用，仍可能重新学到。关闭学习后，现有表达也不再用于生成。

## 配置

新配置都有默认值，已有 `.env` 不添加也能生效。需要调整时加入以下内容，重新创建机器人容器：

```dotenv
CONVERSATION_DEBOUNCE_MS=900
CONVERSATION_FOLLOWUP_SECONDS=120
BOT_ALIASES=喵喵,小喵
EXPRESSION_LEARNING_ENABLED=true
EXPRESSION_TTL_DAYS=30
```

`CONVERSATION_DEBOUNCE_MS=0` 关闭收齐等待；`CONVERSATION_FOLLOWUP_SECONDS=0` 关闭免 @ 接话；`EXPRESSION_LEARNING_ENABLED=false` 同时关闭学习和使用。`BOT_ALIASES` 默认留空，只匹配完整称呼或句首称呼加中文逗号、英文逗号、空格、中文问号；正文中偶然出现昵称不会触发。

自然接话继续使用现有 `random` 模型路由；直接提问被补充替代时保留 `mention` 路由。OpenCode、API Key、故障转移和供应商配置都通过现有适配层完成。

## 升级和验证

数据库在首次启动时事务性升级到 schema 3，保留旧消息与已确认记忆，增加发言者编号、学习来源标记和独立表达表。部署前沿用项目备份流程保存数据库；回退旧代码时需要恢复与旧 schema 匹配的备份。

已在 Node.js 24.15 上通过语法检查及 66 项全量测试。其中新增 17 项覆盖真实业务流程的模拟接口测试、同群排队与多群并行、补充消息替代、发言者与 Topic 隔离、学习来源核对、过期删除、停机排空及旧数据库升级。

真实模型生成和 Telegram 实际群聊效果等待部署反馈。本轮没有使用本机 OpenCode 额度测试，下面是部署后的观察项目，不能当作已测效果：

1. @ 机器人发问题，紧接着补两句，观察是否结合完整输入回应，避免逐句抢答。
2. 回答后直接继续追问，观察是否接上；发“谢谢”后观察是否自然收住。
3. 让其他群友插话，或回复另一名群友，观察是否避免把所有话都当作对它说。
4. 混合闲聊、吐槽和技术求助，观察是否有语气变化，认真问题是否回答具体。
5. 在不同群和 Topic 查看 `/expressions`，确认表达隔离；删除一条，检查列表确已移除。
6. 如果回复仍然机械，反馈实际使用的模型名称和一段脱敏对话，分别调整人设、表达规则或发言频率。
